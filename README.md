## Why Kiro
 
Kiro is an AI-powered, agentic software engineering platform and IDE working towards Spec-Driven Development (SDD) involving requirements, architecture designs, and working code. Lots to learn and this space (along with my gist) will be my commonplace book for the upcoming hackathon.
 
## Specs (pretty important)
 
| File | Question it answers |
|:--|:--|
| `requirements.md` | **What** should this do? User stories plus acceptance criteria |
| `design.md` | **How** will we build it? Architecture, sequence diagrams, strategy |
| `tasks.md` | **In what steps?** Discrete, trackable implementation tasks |
 
One spec makes a small folder of Markdown under `.kiro/specs/`. For defects there is a variant, the **bugfix spec**. The analysis lands in `bugfix.md` instead of `requirements.md`.
 
## 🎃 Kiroween theme categories
 
- **Resurrection:** bring your favorite dead technology back to life. (chosen theme) 
- **Frankenstein:** stitch a chimera of technologies into one unexpectedly powerful app.
- **Skeleton Crew:** a lean, flexible code template, shown with two distinct applications.
- **Costume Contest:** any app, but with a polished, unforgettable haunting UI where the spooky design enhances the function.

## Using Kiro well (what judges look for)
 Judges want to see Kiro's features used, not just a finished app.
 
- **Specs:** write requirements, design, and tasks before coding, then build from them.
- **Steering files:** record the spooky design system (colors, fonts, tone) so every screen stays consistent.
- **Agent hooks:** for example, auto-check styling or tests on save.
- **MCP:** add one if it makes sense. It's optional.
